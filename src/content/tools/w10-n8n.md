## What it is

**n8n** and **Make** are visual workflow automation tools. You connect **nodes** (n8n) or **modules** (Make): a **trigger** (a form submission, a webhook, a schedule, a chat message) followed by steps (call an API, call an LLM, search documents, apply conditions, send a message, update a sheet). Both support AI steps, and n8n has built-in AI agent, vector store and RAG nodes.

- **n8n:** free cloud trial; **free if self-hosted** (requires some technical setup) under its fair-code licence. Check current plans.
- **Make:** free plan with a monthly operations limit.

## Why PMs use it

No-code workflow tools let PMs build working AI prototypes without engineers: classify messages, answer from documents, create tickets, send replies. Your P4 prototype can run on one of these. It also teaches you how real AI pipelines are structured (Week 10 lessons in action).

## Account setup (free plan)

**n8n (recommended for RAG/agents):**
1. Go to n8n.io → **Get started** (cloud trial) or follow the self-hosting docs if you’re comfortable running it on your laptop (Docker or npm).
2. Create a workspace and open a new **workflow**.
3. Add your **Gemini credential**: Credentials → New → search “Google Gemini” (or “Google PaLM/Gemini API”) → paste your API key.

**Make (alternative):**
1. Go to make.com → **Get started free**.
2. Create a **scenario**. Add a Gemini (Google AI) or HTTP module with your API key.

## Walkthrough A (n8n): a simple RAG Q&A workflow

### 1. Prepare your knowledge
1. Collect 10–30 documents for your P4 domain (FAQ answers, policy text you wrote, help content you’re allowed to use) in a Google Drive folder or as text files.
2. Clean them: one topic per document, clear headings.

### 2. Build the indexing workflow
1. Add a **Manual trigger** node.
2. Add a node to **read documents** (e.g., Google Drive “Download file” or “Read files”).
3. Add a **Default Data Loader** + **Recursive Character Text Splitter** (chunk size ~800 characters, overlap ~100) to chunk the text.
4. Add an **Embeddings** node (Google Gemini Embeddings) using your credential.
5. Add a **Vector Store** node (n8n offers a simple in-memory vector store for prototypes; Supabase, Pinecone and others for persistent storage) in **Insert** mode.
6. Run it once. Check the output: number of chunks inserted.

### 3. Build the question-answering workflow
1. Add a **Chat trigger** (n8n provides a test chat window) or a **Webhook** trigger.
2. Add an **AI Agent** node (or a “Question and Answer Chain” node) with:
   - **Chat model:** Google Gemini, your chosen model, low temperature.
   - **Tool / retriever:** the same Vector Store in **Retrieve** mode, top-k = 4.
   - **System message:** your P4 system prompt (answer only from retrieved content; cite the source title; say when not found).
3. Open the test chat, ask 5 questions from your golden set, and inspect each step’s input/output in the execution log (this is basic tracing).

### 4. Add guardrails
1. Add an **IF** node after the answer: check length, check that a source is cited (contains “Source:”), check for banned content.
2. Route failures to a fallback message (“I couldn’t find that. Here’s how to contact us.”).

### 5. Run your eval set
1. Create a second workflow: **Manual trigger** → **Google Sheets: read rows** (your 50 golden inputs) → **Loop** → call the Q&A workflow (or the same agent node) → **Google Sheets: append** output next to each input.
2. Then label in PM Path’s Eval Labeler.

## Walkthrough B (Make): a classify-and-route workflow

1. **Trigger:** Google Forms “Watch responses” (or a Webhook).
2. **Module:** Google AI/Gemini “Generate content” (or HTTP request) with your classification prompt and JSON output.
3. **Router:** branches by the `intent` field (e.g., refund / delivery / other).
4. **Each branch:** call an API or look up a sheet, then generate a reply with a second LLM module.
5. **Final step:** append the result to a Google Sheet (or send an email).
6. **Run once**, check each module’s output bubble, then schedule or activate.

## Tips

- **Start with the smallest working path** (trigger → LLM → output), then add steps.
- **Pin data** while building: n8n lets you pin a node’s output so you don’t re-run expensive steps.
- **Watch execution limits** on free plans; batch your eval runs.
- **Keep credentials in the tool’s credential store**, never in plain text nodes.
- **Export your workflow JSON** (n8n: ⋯ → Download) and screenshot the canvas for your P4 case study.
